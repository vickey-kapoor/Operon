# Splitting the AgentLoop God-Object: 2,364 Lines Into Five Focused Modules

**Operon Engineering Notes — Week of 2026-05-03**

## Architectural Win of the Week

Commit `f723775` decomposed `src/agent/loop.py` from a 2,364-line god-object into five single-responsibility modules: `AnchorCache` (127 lines), `ProgressTracker` (483 lines), `RetryHardening` (170 lines), `StepArtifactsManager` (93 lines), and `adaptation.py` (69 lines). The residual `loop.py` is now 1,951 lines and is nearly pure orchestration — it owns the stage transitions and nothing else.

The most structurally significant extraction was `adaptation.py` and the `strategy_for_failure()` function. Before, the loop determined in-step adaptation strategy by instantiating a `LegacyContractBundle` via `LegacyOperonContractAdapter`, passing it through `UnifiedOrchestrator.process_step()`, and reading `after.adaptation_strategy` back. That round-trip translated `FailureCategory` → `FailureType` in the adapter, then `FailureType` → strategy string in the orchestrator — two type system crossings, two failure modes, and a dependency on the runtime contract layer for something that is purely a lookup table. `strategy_for_failure()` collapses both steps into a single `dict[FailureCategory, str]` keyed directly on the existing enum. The unified orchestrator call now runs only for observability (benchmark runners read `retry_count`/`last_failure_type` from unified state), and that's annotated in the loop with a comment explicitly marking it as non-functional. The adaptation path is now impossible to break by changing the contract schema.

The `ProgressTracker` extraction fixed a subtle bug in the same commit: `_meaningful_progress()` was returning `is_novel_action` instead of `False` when screenshots were unavailable. Since `is_novel_action` defaults to `True`, this silently disabled loop detection any time the before/after screenshot comparison failed — a corrupt capture would bypass the infinite-loop guard for the entire step. Moving progress detection into a tested module with explicit return paths caught this and fixed it.

## What Shipped

### Execution / Subprocess Hygiene (Focus Theft Trilogy)

- `0afaca3` — `AgentLoop.start_run()` gated `reset_desktop()` (Win+D) behind `self.environment is DESKTOP`. Browser-mode runs were unconditionally minimizing the user's foreground window at every task start. Five tasks = five focus steals.
- `6fcd64e` — Added `_NO_CONSOLE = subprocess.CREATE_NO_WINDOW` on win32 / `0` elsewhere to five subprocess call sites: `_app_activate_browser_window`, `_chrome_process_ids`, `taskkill` cleanup, `shell=True` app launch, and the HITL PowerShell balloon notifier. Each spawned `conhost.exe`, which flashes briefly and steals focus. Even with `-WindowStyle Hidden`, the WMI COM initialisation grabs the foreground on some Windows configs.
- `c8d79d2` — `NativeBrowserExecutor.ensure_session()` called `_chrome_process_ids()` twice per session (before and after `chromium.launch`) to compute `browser_pid`. The PID is only consumed by `_bring_browser_to_foreground`, which is already gated to non-headless runs. In headless mode both calls now short-circuit: no PowerShell, no WMI, no possible focus event. One test verifies headless `ensure_session` never invokes `_chrome_process_ids`.

### Memory / State

- `2446078` — `wrap_subgoal(prefix, current)` in `src/agent/subgoal_utils.py` makes subgoal prepending idempotent. The old pattern was `state.current_subgoal = f"{prefix}: {state.current_subgoal}"` at five independent call sites (one in `progress_tracker.py`, four in `recovery.py`). Consecutive firings produced recursive nesting that blew past `MemoryRecord.subgoal`'s 200-char Pydantic cap and crashed the run with `ValidationError`. `wrap_subgoal` strips any leading occurrences of `prefix` before re-prepending so repeated calls are idempotent. `truncate_subgoal()` provides a defensive schema-boundary cap for any future call site that skips the helper. 12 tests cover idempotency, pathological prefixes, and integration with the real 200-char `MemoryRecord` cap.

### Policy

- `5a1ca97` — `CombinedPolicyService.choose_action()` previously raised `PolicyError("No cached decision available")` when `PolicyCoordinator` triggered a re-plan (e.g., `_reject_premature_stop` fires when the LLM emits `STOP` before any substantive action). Combined services bake perception+policy into one call and cache the result; a second `choose_action()` within the same step found the cache empty and crashed the suite. The fix re-issues a fresh combined LLM call against the same screenshot path, picking up any advisory hint the coordinator just appended. For split services this was never a problem because they invoke the policy LLM independently; combined services had no fallback.

### Schema / Benchmarks

- `5bb69a0` — `AgentAction` allows `text` on `STOP` for info-retrieval tasks. The WebArena `string_match` evaluator was reading only the perception summary at run end; if the agent navigated correctly but the target string never appeared verbatim in an OCR'd element label, the eval returned `False`. The agent now sets `action.text` on the final STOP to the answer string (e.g., intent "Find the year Python was released" → `stop(text="1991")`). `_extract_final_text` in `src/benchmarks/webarena.py` prefers `stop.text` and prepends it to the perception fallback corpus.

### Infrastructure / Refactor

- `f723775` — AgentLoop split (see Architectural Win). Also: per-step stage timings written to `step_timing.json` via `_record_stage(name, t0)` calls at each `_trace` point; `run_logger(run_id, step)` returns a `LoggerAdapter` binding `run_id[:8]` and `step` to every record for log grep across concurrent runs.
- `7ae3855` — `StressRunner` executes each task `k=3` times with seeded window position randomization and computes `ReliabilityScore = successes / (tasks × k)`. `compute_trajectory_drift()` measures mean pixel distance between click coordinates in successful vs. failed runs at matching step indices. `PostRunReflector.reflect()` is now gated by `reliability_score == 1.0`; episodes are only written to `episodes.jsonl` when every repetition succeeded — the Golden Path gate.
- `bf93977` — `VerificationStatus.STABLE_WAIT` emitted when screen is actively changing post-action (`> CURSOR_ONLY_THRESHOLD` pixel diff) but outcome not yet confirmed. Loop waits 200ms, re-captures, re-verifies once, then downgrades to `UNCERTAIN` if still moving. `RollingElementBuffer` (renamed from `SpatialCache`) gains ghost TTL tracking: `_active_ghosts` dict with `_GHOST_TTL_FRAMES=2`; `update_ghosts()` ages/purges stale ghosts each frame.
- `19720f2` — Integration workflow added; backend smoke tests cover the desktop and browser executor paths in CI.

## Cold Post-Mortem

**Focus theft (3-PR series, #26/#27/#29)** — `reset_desktop` in browser mode; `conhost.exe` flash from subprocess spawns; WMI COM init in headless `_chrome_process_ids`. Root cause: browser-mode and desktop-mode paths share code that assumes a desktop presence. Fixed across three commits over the same day, indicating the original scope was underestimated at each fix. Severity: **degraded** (user's active window interrupted; agent behavior unaffected).

**Recursive subgoal overflow (#28)** — `ValidationError` crash on `MemoryRecord` write after 3-4 recovery/stall triggers. Root cause: five independent call sites used string interpolation without checking for existing prefix. Present since subgoal recovery was introduced; only surfaced under the medium WebArena suite's 5-task continuous run (single-task runs rarely trigger both recovery and stall detection on the same subgoal). Severity: **blocking** (kills the run mid-task; memory write fails; all subsequent steps aborted).

**Combined service cache miss (#24)** — `PolicyError` crash on re-plan. Root cause: `CombinedPolicyService.choose_action()` assumed it would be called exactly once per step. `_reject_premature_stop` and `_reject_hallucinated_target` each trigger a second `choose_action()` call. The combined architecture has no recovery path for this; split services never had the bug because they call the policy LLM independently. Severity: **blocking** (suite crashes on the affected step; recovery layer never reached).

**Loop detection silently disabled (from #22 audit)** — `_meaningful_progress()` returning `is_novel_action` on screenshot unavailability. Root cause: early-return path was missing a `return False`. A corrupt or missing capture frame during an in-step retry would set `is_novel_action=True` and mark the step as having made progress, resetting the no-progress counter. Severity: **degraded** (could mask infinite loops on flaky capture paths; `MAX_NO_PROGRESS_STEPS` would never fire for affected steps).

**Episode hint silent overwrite (from #22 audit)** — `prepare_hints()` and `choose_action()` in `PolicyCoordinator` assigned `_advisory_hints` directly, clobbering any episode hint set by `_try_episode_hint`. Root cause: `set_advisory_hints` had implicit replace-all semantics used by code that intended append semantics. Replaced with `add_advisory_hints` plus `source` tagging. Severity: **degraded** (optimal trajectory hints never reached the LLM on steps where memory hints also fired; episode replay quality reduced silently).

**Path traversal in `run_id` validation (from #22 audit)** — `GET /run/{id}` and `_ensure_run_dir` did not validate `run_id` against `[A-Za-z0-9_-]` or use `resolve()`/`is_relative_to()`. A crafted `run_id` containing `../` could read or write outside `runs/`. Fixed with regex validation + path containment check. Severity: **blocking** (security; external API surface).

**Unified contract layer is now dead weight** — `LegacyOperonContractAdapter` + `UnifiedOrchestrator.process_step()` are invoked in the loop under a `try/except` that swallows failures and treats the result as optional. The functional role (adaptation strategy) moved to `adaptation.py`. The remaining observability role (benchmark runner reads `retry_count`) could be served by reading `AgentState` directly. The contract translation adds ~1 `model_construct()` call per step and keeps two parallel type systems alive. Not yet cleaned up.

## What's Next

The unified contract layer (`LegacyOperonContractAdapter` → `UnifiedOrchestrator`) is now purely observational but still invoked on every step with failure-swallowing error handling — a pattern that hides bugs and keeps dead code load-bearing. The most important open problem is auditing whether any benchmark runner actually reads `unified_state_for_run()` output that can't be served from `AgentState` directly, and if not, deleting the contract translation path entirely.
