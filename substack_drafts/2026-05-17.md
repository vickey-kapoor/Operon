# The Runtime Contract Bus Is Dead: 13,600 Lines Deleted in One Week

**Operon Engineering Notes — Week of 2026-05-11**

## Architectural Win of the Week

The centerpiece this week was the surgical removal of the `src/runtime/` contract bus, `VideoVerifier`, `PostRunReflector`, and `AnchorCache` — approximately 5,200 lines deleted in commit `0ce79c0`, layered on top of 8,420 lines of benchmark and DOM infrastructure removed in `09cc34b`. The two-phase purge totals ~13,620 lines and leaves `AgentLoop` with a flat, linear critical path for the first time since its original implementation.

**The contract bus problem.** `src/runtime/` was a "phase migration" layer: `LegacyOperonContractAdapter.bundle()` converted the native `AgentState`/`ScreenPerception`/`PolicyDecision`/`ExecutedAction`/`VerificationResult` tuple into a `LegacyContractBundle`, which `UnifiedOrchestrator.process_step()` consumed to produce a `UnifiedStepResult` with an updated `AgentRuntimeState`. The ostensible purpose was observability and benchmark state tracking. The problem: by the time `0ce79c0` landed, a comment in the loop already read *"Best-effort unified contract conversion for observability/benchmarks"* — the retry decision had been fully decoupled to `strategy_for_failure()` operating directly on `FailureCategory`. The contract bus was running on the hot path every step inside a `try/except (RoutingError, ValueError)` that silently swallowed failures. A conversion bug produced no runtime signal. Additionally, `self.unified_states: dict[str, AgentRuntimeState]` grew unboundedly — runs were only evicted when `AnchorCache.discard_run()` was called, and since both were removed atomically, no eviction path existed. Every completed run left a permanent `AgentRuntimeState` in memory for the lifetime of the server process.

**The VideoVerifier tax.** `VideoVerifier` fired when `screen_change_ratio < SCREEN_CHANGE_THRESHOLD` and the policy expected `ExpectedChange.CONTENT`, `NAVIGATION`, or `DIALOG`. The sequence: record a 3-second clip, call `executor.execute_with_recording()` (re-execute the action), send the clip to Gemini. Per-step overhead: 5–8 seconds on uncertain steps. "Uncertain" steps cluster at page-transition boundaries — exactly the moments where additional latency hurts most. The verifier had three confidence bands (< 0.2 → `FAILURE`, 0.2–0.5 → `UNCERTAIN`, ≥ 0.5 → `SUCCESS`) implemented across ~150 lines in `_maybe_video_verify()`. Without a benchmark suite to validate the signal quality against ground truth, this was dead weight on the critical path guarded by a feature gate that was always on.

**What replaces them.** The retry logic is now a direct call: `strategy = strategy_for_failure(recent_failure, verification_failure=..., verification_uncertain=...)`, with `_MAX_ADAPTATION_RETRIES = 3` as a local constant. The `UnifiedOrchestrator.max_retries` field is gone. The `AnchorCache` has no replacement: coordinate snap-back for TYPE actions was an over-fit edge case; if the element drifts, the Visual Servo (`_region_has_content()`) detects the shift and the retry-hardening path handles re-resolution via `DeterministicTargetSelector.reresolve()`.

## What Shipped

**Execution / Core**

- `0ce79c0` — Removed `src/runtime/` (UnifiedOrchestrator, LegacyOperonContractAdapter, AgentRuntimeState, Phase5BenchmarkRunner), `video_verifier.py`, `reflector.py`, `anchor_cache.py`. Cleaned all call sites from `loop.py`, `verifier.py`, `routes.py`. 7 test files and stale cases in 4 others removed. 472 tests passing post-delete.
- `09cc34b` — Removed 8,420 lines: static HTML command-center/console/dashboard/benchmarks, `src/api/benchmark_suite.py`, `src/benchmarks/` (webarena, registry, form plugin, eval harness), `src/evaluation/`, `src/store/cost.py`, all `scripts/` utilities. DOM/accessibility overlay removed from browser manager and React UI (violated vision-only contract). CI matrix trimmed to single Ubuntu 3.11 runner. 622 tests passing.

**API / Routes**

- `214819f` — Browser auto-run tasks now tracked in `_auto_run_tasks: dict[str, asyncio.Task]` in `routes.py`. Before: bare `asyncio.create_task()` discarded the returned `Task` immediately. Stop routes couldn't cancel the background loop, so stop-then-start left the old loop racing against the new one on the same `run_id`. Fix introduces `_schedule_auto_run()` (deduplicates via `run_id` key), `_cancel_auto_run()` (awaits cooperative cancellation with `CancelledError` swallowing), and `_auto_run_done_callback` that removes the entry from `_auto_run_tasks` on completion.
- `d127969` — Stop routes now await `_cleanup_completed_run()` after transitioning a run to `CANCELLED`. Before, Playwright session teardown wasn't called on cancellation — the browser process remained alive. The fix is idempotent on already-terminal runs via the `cancelled_now` guard flag.
- `de822e7` — `OPERON_TEST_SAFE_MODE` guard extended to skip browser startup and auto-run scheduling in `routes.py`. Prevents real Playwright launches during the unit test suite.

**Policy / Backends**

- `04242f1` — `BrowserComputerUseBackend._advisory_hints` promoted from `list[tuple[str, str]]` to `dict[str, list[tuple[str, str]]]` keyed by `run_id`. `FallbackBackend._clear_inactive_hints()` now passes `run_id` to `clear_advisory_hints()`. Before: in multi-run server sessions, advisory hints (memory hints, RAG rule traces) accumulated in a shared flat list. A run completing on the secondary backend would call `clear_advisory_hints()` on the inactive backend, wiping the primary's hints for the next run with no run-id check. Cross-run hint contamination was the failure mode.

**Capture**

- `61908ab` — `mss.mss()` is deprecated in mss 10 (bumped in `0223192`). All 8 call sites in `src/executor/desktop.py` now go through `_mss()`, which does `getattr(mss, "MSS", mss.mss)()` to prefer the non-deprecated constructor when available.

**Tauri desktop wrapper**

- `77195f4` — Tauri v2 desktop wrapper scaffold landed with `src-tauri/` crate skeleton.
- `571ee52` — `tauri-plugin-log` wired for runtime logging.
- `b73dee7` — `Cargo.lock` committed.
- `7aaa87d` — CI `cargo check` job added for `src-tauri/`.

**Dependencies**

- `0223192` — Major version bumps: Pillow 12, mss 10, google-genai 2.x, cryptography 48 (Python); Vite 8, TypeScript 6, `@vitejs/plugin-react` 6 (npm). Build target updated to `es2022/chrome120`, minifier switched to oxc.

## Cold Post-Mortem

**Episode extraction path is now a dead end.** `memory_store.record_step()` still writes `MemoryRecord` entries to `memory.jsonl` on every step. `MemoryStore` still exposes `add_episode()`, `get_episode()`, `_load_episodes()`, `_write_episodes()`. But `PostRunReflector` — the only caller of `_filter_one_shot_steps()` and `_extract_episode()` — was deleted in `0ce79c0`. Episodes will never be written. `get_hints()` still queries `memory.jsonl` step records for hint injection, so that path functions. But the compressed optimal-trajectory store (`episodes.jsonl`) is permanently orphaned; the per-step `record_step()` call at line 693 of `loop.py` now writes data that improves nothing. Severity: **degraded** — the agent operates but loses cross-run learning optimization. The orphaned `_load_episodes` / `_write_episodes` / `add_episode` methods in `memory.py` are dead code.

**`_advisory_hints` sentinel bucket race.** Fixed in `04242f1`, but `_render_prompt()` in `BrowserComputerUseBackend` pops `state.run_id` then falls back to the `""` sentinel bucket (used by tests). In production, if `add_advisory_hints()` is called before `run_id` is populated on `state` — e.g., during the `start_run()` warmup path — hints land in `""` and are consumed by whichever run renders next. Low probability but non-zero in concurrent multi-run server sessions. Severity: **degraded**.

**No cancellation-path Playwright teardown test.** `d127969` fixed browser session cleanup on `CANCELLED`, but `tests/api/test_task_modal.py` asserts HTTP status codes, not that `_cleanup_completed_run` actually invoked browser teardown. The fix is verified only by manual inspection. Severity: **cosmetic**.

**CLAUDE.md describes deleted components as live.** The architecture section still describes VideoVerifier (+5–8s latency), PostRunReflector, AnchorCache, `unified_states`, and the `src/runtime/` package as active components. The step sequence listed (12 steps including reflect) diverges from the actual loop. Severity: **cosmetic** — documentation debt that will mislead anyone onboarding from the README.

## What's Next

The memory system is half-deleted: step records accumulate in `memory.jsonl` with no corresponding episode extraction consuming them. The decision is binary — reimplement episode extraction without the `src/runtime/` dependency, or excise the episode path entirely and simplify `MemoryStore` to step-record-only hint injection. Given the trajectory this week, the latter is almost certainly correct and would eliminate another ~200 lines from `memory.py` and the dead `episodes.jsonl` write path.
